# Cover letter writer

## Inputs

- The saved job: title, company, named skills, requirements, location and source.
- Confirmed profile facts: recent relevant role, one or two projects, skills and motivation stated by
  the user.
- Optional user-provided detail: why this company, a referral, a portfolio piece, an accessibility
  need. Do not invent any of these.

## Structure

1. Greeting: use a named recruiter only if the listing provides one; otherwise "Hiring team".
2. Opening: the role, where it was found, and one specific reason for applying that is true.
3. Evidence: one or two examples from confirmed experience that map to the listing's main needs.
4. Fit: address a gap honestly if it is central, or explain adjacent experience.
5. Close: availability, willingness to discuss, thanks. No pressure or invented urgency.

Keep it to one page. A cover letter is not a resume in paragraph form; it connects the evidence to the
role.

## Personalisation

- Reference the company's actual product/team only if the job text or a source the user approved says
  it. Do not invent funding, culture or recent news.
- Mirror the listing's vocabulary when it is accurate.
- If the user supplies a personal reason, preserve its meaning and tone; do not exaggerate it.

## Truth and tone

- No fabricated achievements, metrics, degrees or authorization.
- No "I am the perfect fit" claims that the evidence does not support.
- Match the user's requested tone: professional, concise or enthusiastic. Enthusiastic is not
  overclaiming.
- Avoid generic phrases that could apply to any company.

## Workflow

1. Generate a draft with the career tool.
2. Show the user the draft and the facts it used.
3. Let the user edit; save a new version (never overwrite).
4. Run the truth check: contact details, years, credentials, skills, employer names.
5. Attach the saved document to the application.

## Failure handling

- Missing job: ask for the saved listing or create one first.
- Missing evidence: write a shorter, honest letter rather than inventing a story.
- Tone request conflicts with truth: keep truth, explain the trade-off.
- Export failure: preserve the text and report the error.

## Review checklist

- [ ] Names the correct role and company.
- [ ] One concrete, verified example.
- [ ] No invented company fact.
- [ ] No unsupported superlative or metric.
- [ ] Contact details match the profile.
- [ ] Saved as a new version.
